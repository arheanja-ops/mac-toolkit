# TUI-2 — Clean interactivo dentro del TUI — Design Spec

**Date:** 2026-11-01
**Status:** Draft
**Scope:** mac-toolkit CLI (`internal/tui/`, reutiliza `internal/cleaner` + `internal/core`)
**Roadmap:** sigue a [TUI-1](2026-09-21-tui-k9s.md). Fase TUI-2.

## Problem

Hoy el TUI es 100% solo lectura: sus acciones (Analyze, Status, 4 monitores, Last
report) solo muestran información. Para **limpiar** hay que salir del TUI y correr
`mac-toolkit clean --execute --mode checklist` con prompts en texto plano. Eso crea
la desconexión que reporta el usuario: "lo bonito no hace nada, lo que hace cosas es
incómodo". El TUI se siente poco productivo porque no se puede actuar desde donde se
ve.

TUI-2 trae la limpieza **al TUI**, con checkboxes y un modal de confirmación, **sin
debilitar** ninguna de las garantías de seguridad existentes (dry-run, blacklist,
audit log, gate humano). Reutiliza `internal/cleaner` — no reimplementa borrado.

## Features

### F1: Acciones Preview y Clean en el panel izquierdo

**Panel izquierdo:** nuevo grupo `Clean` con dos acciones:
- `Preview` — corre el análisis y muestra el plan de limpieza (dry-run, como hoy
  `clean` sin `--execute`), en el panel derecho, tabulado y coloreado. Solo lectura.
- `Clean (select & delete)` — abre el **modo selección** (F2) en el panel derecho.

Constraints:
- `Preview` nunca borra; es equivalente a `reporter.PrintCleanPlan` pero tabulado
  para el viewport.
- El grupo `Clean` se añade a `buildActions()`; las acciones de solo lectura
  existentes no cambian. La acción Quit permanece.

### F2: Modo selección con checkboxes (el corazón de TUI-2)

Al elegir `Clean`, el panel derecho entra en un **modo selección** interactivo (un
estado nuevo del modelo, no un viewport de texto):

```
 CLEAN — selecciona qué borrar (espacio marca · a todos los seguros · ⏎ continuar)
 ───────────────────────────────────────────────────────────────────────────
  [x] safe    5.6 GB   dev_caches · brew/pip/npm
  [x] safe    2.2 GB   browser · Chrome cache
  [x] safe   17.0 GB   repos · node_modules (1272)
  [ ] warn    1.4 GB   downloads · requiere revisión (no auto-marcable)
  [ ] danger 32.0 GB   docker · Docker.raw (no auto-marcable)
 ───────────────────────────────────────────────────────────────────────────
  Marcado: 24.8 GB en 3 grupos seguros        [⏎] continuar  [Esc] cancelar
```

Behavior:
1. Lista los dominios/items reclamables del análisis (reutiliza `runAnalysis`).
2. Items **safe** vienen **pre-marcados**. Items **warn/danger** se muestran pero
   **NO son marcables** en TUI-2 (ver Non-goals) — aparecen atenuados con la razón.
3. Navegación: `↑↓` mueve, `espacio` alterna el marcado de un item safe, `a` marca
   todos los safe, `n` desmarca todos, `Esc` cancela y vuelve, `⏎` continúa al
   modal de confirmación (F3).
4. El pie muestra el total marcado (tamaño + conteo) actualizado en vivo.

Constraints:
- **Solo items `SafeToDelete == true && Risk == safe` son marcables.** Cualquier
  intento de marcar un warn/danger es un no-op (defensa en el modelo, no solo en la
  UI).
- Si no hay items seguros, muestra "Nada seguro para limpiar" y solo permite Esc.
- Entrar en modo selección NO borra nada; es puramente preparación.

### F3: Modal de confirmación dentro del TUI (gate humano)

Al pulsar `⏎` en el modo selección, se superpone un **modal** centrado:

```
        ┌─ Confirmar limpieza ──────────────────────────┐
        │                                                │
        │  Vas a borrar 3 grupos · 24.8 GB               │
        │  Esta acción es irreversible.                  │
        │                                                │
        │  Escribe "si" y pulsa ⏎ para confirmar:        │
        │  > _                                           │
        │                                                │
        │  [Esc] cancelar                                │
        └────────────────────────────────────────────────┘
```

Behavior:
1. Muestra conteo y tamaño total exactos de lo marcado.
2. El usuario debe **escribir "si"** (o sí/yes/y) y pulsar `⏎`. Cualquier otra cosa,
   `Esc`, o vacío → cancela, no borra.
3. Al confirmar: ejecuta el borrado vía `cleaner.NewGenericCleaner(false, true).Clean()`
   sobre los items marcados — **la misma ruta que el CLI**, que ya consulta la
   blacklist por cada item.
4. Durante el borrado, el panel muestra progreso (spinner o barra). El borrado corre
   en un `tea.Cmd` (goroutine) para no congelar el event loop.
5. Al terminar: escribe el **audit log** (`reporter.AuditReporter`) igual que el CLI,
   y muestra un resumen: "Liberaste X GB · N items · audit: <ruta>".

Constraints:
- **El gate es inquebrantable:** sin un "si" explícito, no se borra. Reusa la misma
  lógica de afirmativos que `confirmFinalDeletion` en `cmd/clean.go` (extraer a una
  función compartida en `core` para no duplicar: p. ej. `core.IsAffirmative(string) bool`).
- El borrado pasa SIEMPRE por `cleaner.Delete`, que respeta la blacklist. El TUI no
  borra por su cuenta.
- El audit log se escribe SIEMPRE que haya ejecución real, igual que el CLI.
- Si el modelo detectara algún item no-safe marcado (no debería ocurrir por F2),
  aborta el borrado completo por seguridad.

### F4: Atajos rápidos (productividad tipo k9s)

Teclas globales en el TUI (cuando no se está filtrando ni en un modal):
- `a` → ejecuta Analyze
- `d` → ejecuta Doctor (si se integra; si no, se pospone a TUI-3)
- `c` → abre el modo selección de Clean (F2)
- `p` → Preview

Constraints:
- Los atajos solo disparan acciones ya existentes; no crean rutas nuevas de borrado
  fuera de F2/F3.
- `c` abre selección (que NO borra); el borrado sigue exigiendo F3.

## Reutilización (no se reimplementa nada destructivo)

| Necesidad | Se reutiliza |
|-----------|--------------|
| Analizar | `cmd.runAnalysis` / `core.RunAnalyzers` |
| Borrar items | `cleaner.NewGenericCleaner(false,true).Clean()` |
| Blacklist | `cleaner.Delete` (ya la consulta) |
| Audit log | `reporter.AuditReporter.WriteAudit` |
| Afirmativo del gate | `core.IsAffirmative` (extraído de `confirmFinalDeletion`) |

## Data model (adiciones a `internal/tui/`)

```
// Nuevo estado del modelo para el modo selección/confirmación.
mode int            // normalMode | selectMode | confirmMode | cleaningMode
selectable []cleanRow  // filas del modo selección
type cleanRow {
  item     core.CleanableItem
  marked   bool
  markable bool    // true solo si Risk==safe && SafeToDelete
}
confirmInput string // lo que el usuario teclea en el modal (F3)
cleanResult  *cleanSummary // resultado tras borrar (freed bytes, count, audit path)
```

## Non-goals (TUI-2)

- Marcar/borrar items `warn` o `danger` desde el TUI → futuro (TUI-2.1), requerirá
  confirmación por item y advertencias reforzadas. En TUI-2 solo se borra lo `safe`.
- Operaciones Docker (backup/cleanup/compact) desde el TUI → futuro.
- Deshacer/papelera: el borrado sigue el comportamiento actual del cleaner.
- Panel Doctor completo → TUI-3 (el atajo `d` puede quedar deshabilitado si no se
  integra aquí).

## Testing

- **Marcabilidad:** test de que `cleanRow.markable` es true SOLO para safe; alternar
  un warn/danger es no-op.
- **Gate:** test de que confirmMode con input distinto de afirmativo NO produce
  borrado (reusa/compara con los tests de `confirmFinalDeletion`).
- **Ejecución:** test con un cleaner inyectado/temp que verifique que solo los items
  marcados safe llegan a `Clean()`, y que un item no-safe marcado abortaría.
- **core.IsAffirmative:** tabla de afirmativos/negativos (migra los casos del test de
  clean).
- **Transiciones de modo:** `Update` con teclas sintéticas (`c`, espacio, ⏎, Esc)
  verificando normal→select→confirm→cleaning→normal.
- No se testea el render pixel a pixel.

## Seguridad (resumen — no se relaja nada de SAFETY.md)

- Dry-run sigue siendo el default de `clean` CLI; el TUI añade una ruta de borrado
  que exige selección explícita + "si" en el modal.
- Blacklist + audit log intactos (se reutiliza el cleaner/reporter).
- Solo `safe` es borrable desde el TUI en esta fase.
- Actualizar `docs/SAFETY.md`: añadir que el TUI, a partir de TUI-2, puede borrar
  items **safe** únicamente, tras selección explícita y confirmación "si" en un modal,
  pasando por blacklist y audit log.
